# Successor permanent-asset basis checkpoint

## Scope

Additive inactive `successor-career-assets-v1` drafts only. This is a prerequisite
for a new terminal-capable owner, not an expansion of owner111 admission.
Production source, existing save slots, pitch/proof signatures and original
visuals remain unchanged.

The read-only asset basis checks successor receipt policy and player progress,
projects strictly validated aggregates into unchanged stadium/legend policies,
validates existing pennant/plaque records, and reconstructs the permanent ledger.
It retains original earned-player thresholds, credit pairing, award-time eras and
unknown-evidence behavior. No grant, purchase, completion or save is performed.
Plaque capture is a separately explicit, staged in-memory metadata operation;
it cannot deliver an asset or persist a career.

These structural adapters require an owner decoder to replay physical results
and transactions first. They cannot distinguish invented structurally consistent
stats from earned results by themselves. They must not become an alternate
save-admission route.

## Verification

Run `python tools/test_successor_signature.py --assets-fixture <isolated-owned-save>`.
The runner verifies draft hashes and restores into a fresh project with isolated
HOME/XDG directories. Three cold processes restore the actual owner111 three-game
checkpoint. Checks cover unchanged empty permanent income/progress/awards,
byte-identical ledger, original player access, repeat idempotence, malformed
receipt/progress/assets/current/plaque rejection, and untouched source bytes.

Separately labeled synthetic operands compare original stadium totals and plaque
thresholds, credited-game minima, three-season requirement, null evidence,
prospective award era, forged statistics and award-completion provenance.
Synthetic histories are not physical-game or completed-career evidence.

Completed-income ledger reconstruction and delivered plaque/pennant integration
are not established by the unfinished actual fixture. These remain required in
terminal-owner tests. This checkpoint proves no completed successor season,
next-season ownership, Dynasty, visual playtest, or distributable build.

On 2026-11-17 Godot 4.6.3 completed all three suites with PASS markers and no
script errors in a fresh isolated run. Source fixture bytes were unchanged.
Python compilation, manifest byte/hash checks and `git diff --check` also passed.
An independent read-only integration audit found no blocking defect and identified
the completed-income/delivered-award coverage limit recorded above.

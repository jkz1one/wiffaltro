# Immediate physical-report validation reuse

Only the generalized family's resolver changes. An existing validated-report
comparison path previously required original base-class identities and could
never activate for Game114. It now requires exact current Runtime/Build/Fixtures
scripts, ordinary Codec scope, the original receiver/ownership and transient
exclusions, bounded JSON-value graph validation and a nonempty current catalog.

The report is detached before full self-validation. The same detached report is
then compared immediately against freshly reconstructed fixture, request, seed,
field, roster, paid ownership, recipe, workload, tactics and source context.
Nothing survives the synchronous call. No global/persistent memo, saved validity
bit, caller-supplied proof or skipped expected-state comparison is introduced.
The private false option repeats full self-validation for equivalence testing;
public resolution uses the eligible path or the unchanged full fallback.

Static call routing removes one repeated Report.valid invocation per eligible
resolve (two to one). It does not eliminate the initial from_data/envelope
validation, and this count is structural evidence, not a runtime counter.

## Verification status

Fresh actual Standard and Dugout rounds are regenerated under this exact source;
old reports are not relabeled. Regression reconstructs pre-round operands from
strictly decoded current paid evidence, verifies request keys and eligibility,
compares ABBA output/error/cursor/needed values, tests tampering and fallback,
and preserves input save/source bytes. Final outcomes and timing follow below.

An independent unbound frozen-B2 microprofile found median catalog signature
282ms, report self-validation749ms, core720ms and matches1266ms over three
samples each. Its bound source and save bytes were unchanged. These overlapping
operations include shared signature/context work, so they do not isolate replay
cost. Concurrent tests make all timings diagnostic, not product latency promises.

Final-source Godot4.6.3 checks passed for both profiles: regenerated actual human
plus two NPC games, earned pack purchase, exact paid cold reopen, strict current
fixture reconstruction, each optimized-call eligibility assertion, ABBA exact
result/error/cursor/needed parity, deep-copy poisoning, report/request/seed/field/
catalog/player-stat/ownership tampering and guarded full-validation fallback.
Original paid save bytes and decoded state stayed unchanged. The additional
eligibility assertions changed only the unbound test, not any source identity;
the earlier test copy/logs were retained and Dugout reran with the final assertions.

Mean resolver times across two authentic NPC fixtures, two samples per mode
per fixture, with concurrent tests:

# Genuine successor career: actual active-round integration

## Scope

An additive live-owner domain starts a genuine first Dugout club before drafting.
It retains the frozen draft-owner reader and slot, original source, standalone
successor, and unowned League successor. The live owner has a separate envelope,
source identity and save path. It does not attach a career to a played standalone
checkpoint or grant completion income.

The new decoder reconstructs birth and initial access before replaying draft,
Build events and actual match evidence. Pending projection retains the genuine
owner. Career synchronization derives all progression fields from the validated
season, rather than resetting them to fresh values. Shop purchases synchronize
career progress on the candidate before durable publication.

This is active-run integration, not proof of full career completion, subsequent
runs, title/unlock awards, abandonment, Dynasty, visual playtesting or a
redistributable build. Those remain work ahead. No arbitrary one-round limit is
introduced merely because this checkpoint's gameplay test covers one round.

## Qualification plan

```
python tools/test_successor_signature.py --owner-round --godot /usr/local/bin/godot
```

The isolated test drives the actual App and native game controllers, not fabricated
scores. Separate processes cover human completion/pending save, first AI report,
second AI report/settlement/shop, and final cold reopen. It checks original starting
entitlements and the entire active career row at every meaningful boundary.

The earned pack test also opens the inherited full shop window, verifies singleton
opening and no-spend preview, then forces an isolated save failure. The real retry
button must publish the exact retained candidate once. Tampered receipts, progress,
access and owner identity must fail replay. The old draft-owner slot remains
byte-identical and readable.

## Verified native result

Godot 4.6.3 isolated run `9qy27ptt`, seed `1794849205`: all four processes
passed with the final manifest source bytes. The final cold capture equals the
published slot payload exactly. All five opponent clubs received one reward;
the human reward matched the actual result; one paid development level was applied.
Duplicate round resume and duplicate purchase were inert.

The full shop **pack flow** was exercised through its confirmation and retry
controls. This is not qualification of every shop branch, mouse-driven visual QA,
or responsive UI performance. Save/replay operations are still slow; a separately
verified performance pass is needed without weakening validation.

Pending human and human-plus-first-AI checkpoints were reopened in fresh processes.
The two-AI pending checkpoint was retained and settled in-process, not independently
cold-tested. The original draft-owner slot stayed byte-identical and readable.

An earlier run `nzhx1jbx` was stopped during draft qualification before gameplay.
An independent diagnostic mismatch came from its default-precision JSON serializer,
not a demonstrated production save failure; production already uses full precision.
The new decoder was also tightened to pass its genuinely reconstructed owned pool
to Build restoration rather than the separately ordered draft display pool. No
validator was relaxed. The complete four-process run above used the corrected
source and full-precision persistence.

Raw isolated saves and logs are retained outside source publication. Previous
source domains and their manifests are unchanged.

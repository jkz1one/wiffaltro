# Saved physical season rounds

New Working seasons use the shared real physical AI resolver for other clubs' fixtures. Existing seasons keep their historical score-only resolver. Build41/Career21/opponent policy2 stay unchanged; physical seasons use save46 with a separate version1 evidence archive. Historical Build41 saves remain45. Overall project estimate is **~76%**, not release readiness.

At game end, the actual human score and gameplay evidence save as a pending round while the existing celebration/outro continues. Continue begins sequential offscreen games. The progress lightbox shows the actual clubs, score and inning. Pause stops only the unfinished game; completed games stay checkpointed. On reopening, Resume continues from that prefix. An unfinished physical game restarts from its committed initial match and seed; there is no mid-pitch suspension format.

Completed report writes and final round writes have separate retries. A failed report write keeps that completed report in the current session, allowing a save retry without playing it twice. A failed final write preserves the previous live season and pending checkpoint. Results, own W/L wallets, surviving AI stat purchases and derived career state publish together only after a validated candidate save. Shop access and loadout changes wait for settlement. Normal in-play Gear/sponsor sales still save ownership/refunds immediately and retire effects at the next batter boundary; the centered Equipped entry is unchanged.

Saved replay consumes the required report sequence without running physics. Each envelope binds fixture, deterministic masked seed, field and a hash of actual starting definitions/recipes/deliveries, quality, assignments and workload. Roster, recipe and starting stamina evidence also bind independently. Missing, extra, duplicate, foreign or inconsistent reports fail closed. The standalone report's existing event/statistic validation remains in force. This is consistency validation, not authentication of arbitrary external reports.

Godot's JSON parser can change a full-precision decimal by one floating-point bit. Starting workload comparisons use the project's exact JSON-normalized comparison; there is no broad numeric tolerance. Request hashes and integer ledgers remain exact. A full-season paid-upgrade fixture exposed and now covers this case.

Both post-elimination semifinals and the neutral final use saved physical jobs. Semifinal winners' supported purchases commit before constructing the final match, and eliminated clubs buy nothing. Each club's reward ledger must equal precisely its own played W/L fixtures. No second enemy checkout responds to human shopping.

AI purchasing remains policy2's paid four-stat development and base W/L rewards. Physical reports do not enable finite-pool Gear/sponsors, announcement/tactical use, event income or recruitment policies whose whole contracts remain incomplete. There is no fabricated box score, sponsor stipend or price-to-strength shortcut. Ordinary-season matches retain ordinary fresh stamina; Doubleheader workload carry and legal between-game substitutions remain separate work.

Run the short integration checks with `python tools/verify.py --only season-physical-round --only season-physical-visible --timeout 360`. The full23-game throughput benchmark is explicit: `python tools/verify.py --only season-physical-playoffs --timeout 480`. It is outside default scene selection because its measured whole-season runtime exceeds the ordinary per-scene limit. Required completion markers and engine-error checks are unchanged. Never run suites concurrently.

The full season measured23 actual AI games,3376 physical releases,4462.77 simulated seconds,386.60 seconds of headless wall time and a1,517,377-byte final checkpoint on this environment. Regular two-game resolution visits ranged about21–34 seconds; the final five-game eliminated-team wave took85.31 seconds. This is a throughput baseline, not acceptable release latency or hardware evidence. The UI makes that work visible and cancellable. The subsequent bounded [presentation-cost reduction](PHYSICAL_PRESENTATION_COST.md) retains complete paired report equivalence; its measured runtime is recorded in VERIFICATION. Further optimization requires preserving event/physics equivalence; no cheaper score substitute is selected.

# Detached physical AI match foundation

This describes the standalone shared event-producing resolver foundation recommended in Economy v24. The new Working-season consumer is now integrated in [SAVED_PHYSICAL_ROUNDS](SAVED_PHYSICAL_ROUNDS.md); the runner API itself still does not save, reward or settle. Broader AI acquisition remains gated. The original2026-10-02 checkpoint used Build41/save45/Career21; current physical seasons use save46. Overall is now**~76%**, not release readiness.

`PhysicalMatchRunner` is a reusable Node. Add it to the tree, connect `finished(report)` and `failed(reason)`, then call `start(fresh_match, seed, field_id)`. A rejected start returns false without creating a job. An active job cannot be overwritten. `cancel()` frees its isolated world and emits no completed result. Removing the runner also removes its children. Consumers must never treat cancellation or failure as a scored fixture.

`PhysicalMatchRequest` copies fresh teams, player resources, recipes, starting assignments, carried stamina, batting overrides and initial held/scouting configuration. It rejects partially played states, invalid assignments, overlapping player identities and invalid stamina. The original match, definitions, save and club ledgers remain untouched. This is a fresh-job API, not a midgame suspension/replay format.

The job uses a separate SubViewport/World3D, with render updates and GUI input disabled. PitchingStrategy, BatterApproachModel, pitch trajectory/contact, Jolt ball physics, defenders and MatchState resolve both clubs. Each offense retains only its own observed pitch memory; previous pitch choices are kept per pitcher. Global aim/restart input cannot steer the job. Tree pause freezes it. Human live routing, readiness, pitching input, cameras and result holds retain their existing behavior.

Intro/outro and presentation-only set, windup and ordinary dead-ball waits are omitted for detached execution. Pitch flight and ball-in-play still use the ordinary fixed physics step; no Engine.time_scale, global tick-rate change, score shortcut or invented event is used. The existing home-run hold remains. Detached jobs also omit unnecessary sky/radiance texture allocation, which native shutdown review exposed as a leak in the initial path. Human skies are unchanged. The current implementation still builds other lab presentation nodes to satisfy shared dependencies; this is not a claim of an optimized scene-free kernel or acceptable whole-season cost.

The successful standalone report uses `version:1`, `resolver:physical-ai-v1`. It contains scores, field/seed/time/last half, all eight actual statistic lines, ordered player batting outcomes and committed stances, exact recipe releases/strikeouts, credited fielded outs, per-player initial/capacity/remaining stamina and actual paid release costs, plus compact physical play/read diagnostics. Paid costs describe actual deductions, rather than an estimated fatigue charge; remaining stamina is captured separately so future recovery/refund integration cannot confuse gross cost with net workload.

Validation checks exact field shapes, unique club identities, consecutive appearances, lineup order, offensive/defensive half ownership, recipe membership, batting/statistic totals, score/RBI agreement, release counts/costs, final-pitcher hit/walk/K/out credits and correspondence of physical plays and credited outs/Ks to actual appearances. Serialization uses `JSON.stringify(report, "", true, true)` to retain full floating-point precision. This validation is a consistency boundary, not cryptographic proof or permission to settle an arbitrary report.

The foundation does not execute the proposed finite-pool sponsor announcement, tactical activation, recruitment or acquisition policies. Held copies are copied into the detached match without invented uses. The report is not a complete inventory/sponsor settlement contract. Broader AI eligibility stays gated until every included item's whole contract works in visible and offscreen matches. No flat income, price-to-strength mapping or fabricated box score fills the gap.

The saved fixture consumer now versions/replays evidence without rerunning physics, schedules visible cancellable jobs and publishes one atomic round while preserving old score-only seasons. Read SAVED_PHYSICAL_ROUNDS for supported settlement scope and measured whole-round cost. Doubleheader additionally needs tested legal per-pitcher workload carry. Permanent player packs still require the unselected ownership/pack contract.

Primary references consulted for implementation: Godot's [SubViewport](https://docs.godotengine.org/en/stable/classes/class_subviewport.html) and [Viewport](https://docs.godotengine.org/en/stable/classes/class_viewport.html) documentation for render targets, isolated World3D and GUI input. Engine4.7.2 execution tests verify the actual physics behavior rather than assuming render disabling stops or accelerates simulation.

Verification reports and native diagnostic captures are recorded in VERIFICATION. Native images show real shared gameplay rendering, not a new player-facing spectator screen or human visual/feel approval. Shop/player-inspection acceptance and final cohesive whole-game UI/hardware/feel review remain pending.

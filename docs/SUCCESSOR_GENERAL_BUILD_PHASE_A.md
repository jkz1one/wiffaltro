# Generalized successor family: structural Phase A

A single additive `successor_league_general_v2` family, with separate114
Build/Development/report identity, preserves the frozen109 and owner families.
Recipe data and pitch catalog version7 are unchanged. This phase is not a new
playable entry: all public new-family Runtime/Codec season admission is closed.
No saved owner, inherited entitlement or Dynasty lineage is authorized by a
successful structural Build roundtrip.

## Scope

- Original bare Standard0–4 Build41–44 initialization, without invented League
  headers. Standard d2's NPC draft behavior is a later physical/opponent gate.
- Explicit original Standard0 and eight other League profiles at tiers0–4, using
  unchanged rule, capacity, economy and bank policy.
- Original Scramble permutation and fresh empty Dynasty initialization. Carried
  nonempty Dynasty profiles stay rejected until catalog-aware lineage support.
- Exact inherited exotic proof dispatch to frozen109 or current114 validators;
  per-proof eligibility union and original prices, without counter pooling.
- Build and Development retain inherited proof/start operands through JSON
  restore rather than silently dropping them. These remain structural inputs.
- Separate new source identity binds active shared policy implementations as
  well as table/content signatures. It does not relax an old acceptance path.

## Native checks and limitations

The matrix covers47 structural cases: five bare Standard cases,41 explicit
League/tier cases, and one synthetic inherited-start case. It compares original
bank/capacity/pricing profiles, exact Build/Development JSON roundtrips, roster
profiles, malformed metadata/history rejection and closed public admission.
Base profile checks include every authored player's recipe/mastery/capacity and
Scramble stat policy. Synthetic reroll operands compare original reclamation and
d1 arithmetic without claiming a shop was opened or a paid entitlement earned.

An initial test queried reroll price before any shop visit existed. Both baseline
and new code logged missing-reroll errors, so the runner rejected that run despite
its PASS markers. The test precondition was fixed using detached arithmetic
operands and restoring pristine visits. No frozen source was changed to conceal
that test error. A subsequent independent source review added explicit active
policy-source bindings and source-mutation checks before final verification.

No actual generalized League game, NPC parity, round settlement, paid shop,
season save/reopen, career start, abandonment, venue or Dynasty lifecycle is
qualified here. The copied physical/decoder branches still contain narrow gates
and must be qualified in following phases of this same family. Candidate numeric
profiles are retained, not promoted into new balance approvals. No planned depth
or original development visuals have been removed.

Final-source Godot 4.6.3 verification passed all47 cases in a fresh isolated
project with no script errors. Comment mutations to active pricing, Dynasty-profile
and Build sources changed the new signature; exact restoration recovered both
new and legacy signatures. Manifest byte/hash, Python compilation and diff
whitespace checks passed. This result does not open any public Game114 route.

# General catalog signature composition

Each generalized catalog signature previously evaluated the same Provider twice:
once directly, then again inside the frozen109 catalog signature. The new
implementation evaluates it once and composes the exact frozen109 PURPOSE and
ordered FILES digests before the unchanged generalized composition. Frozen109's
own script is among its hashed files. No frozen source is edited.

This is call-local common-expression reuse, not a persistent cache, serialized
trust marker, alternate admission path or validator bypass. Every public call
reads current Provider inputs and all legacy/current file digests again. Empty
Provider or file digest still fails closed. Report/schema/replay/bank/ownership
validators are unchanged. Source identity includes the generalized catalog script,
so fresh evidence is generated; historical saves are not relabeled or migrated.

## Qualification and timing boundaries

An independent test reference retains the original two-Provider formula. It
checks exact parity before timing, then temporarily changes and removes isolated
current-only and legacy source hash inputs, restoring their exact bytes. Loaded
authored recipe/delivery scalar mutations follow the existing Provider semantics;
this does not invent in-memory hashing authority. Invalid recipe identity and
missing delivery must fail on the next call and recover after exact restoration.

The initial standalone test failed before probes because its JSON roundtrip used
default precision rather than the established full-precision save representation.
Only that test serialization was corrected; production validation was not relaxed.
The failed stage remains evidence. Corrected fresh roundtrip and all probes passed.

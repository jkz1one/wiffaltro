# First-run terminal-owner staging checkpoint

This additive owner112 implementation preserves Game109 and owner110/111 byte for
byte. Its separate format/save path permits only the fresh first Dugout0 run;
existing saves are not imported, relabeled or overwritten. It is not a release
build and does not claim next-season or Dynasty integration.

## Implementation

- Genuine birth precedes every pick and paid Build/physical replay.
- COMPLETE is admitted only after exact replay. The saved row, receipt, assets
  and award metadata are compared against derived values, never trusted input.
- Original reward scales, first-title bonus, player/stadium/award policy and
  permanent ledger are retained. Row/receipt/awards/assets publish together.
- Completed rows are immutable and repeat settlement is inert.
- Separate pending/physical adapters preserve original strict Game109 report
  identity while enforcing the new exact owner script and scope.
- Original presentation and full shop are cloned additively; Resource-retaining
  synchronous facade omits no validators. Terminal receipt display reads only
  the published owner; retained candidates expose retry instead.
- Successful exact retry clears the old failure notice.

Catalog coverage explicitly includes new completion/asset helpers, all ledger
operation sources, and active legacy replay-roster/physical-choice dependencies.
Mutation tests check rejection-sensitive source identity while Game109 identity
remains unchanged. No original signature acceptance list is relaxed.
